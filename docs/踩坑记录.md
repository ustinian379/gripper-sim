# 踩坑记录：把第一个项目推上 GitHub

这份文档记的是**真实发生过的失败**，不是教程。每一条都是先撞上、再排查、最后写下来的。
留着的原因很简单：下次再遇到同类问题，五秒钟能定位，不用重新熬一遍。

---

## 一、安装 Git

### 1. 安装包放在工作区目录里运行，报 `Error 5: 拒绝访问`

```
Setup was unable to create the directory
C:\Users\laydo\AppData\Local\Temp\is-XXXX.tmp. Error 5: 拒绝访问。
```

**现象**：安装包从 `...\deepseek-harness\default-workspace\.scratch\installers\` 双击启动，安装程序连临时目录都建不出来。
**已排除**：目标目录 ACL 正常（属主、Administrators、SYSTEM 都是完全控制），用户自己在该目录下能正常建文件夹，磁盘剩余 425 GB。
**结论**：**安装类 exe 不要从那个工作区目录启动**。复制到桌面再运行，一次成功。
**为什么**：没有定位到具体机制，只知道是"从那个目录启动的安装程序写不了用户目录"。实践上避开即可。

### 2. `winget` 在这台机器上完全不可用

```
winget --version   → 退出码 -1978335231 (0x8A150001)，无输出
Get-AppxPackage    → 拒绝访问
```
App Installer 依赖的 WinRT 接口在当前会话拿不到（沙箱环境限制），不是系统本身坏了。
**替代**：直接下载官方安装包。

### 3. 官方下载源

| 源 | 结果 |
|---|---|
| `github.com` 直链 release | `ECONNRESET` |
| `git-scm.com/download/win` | 可达，但指向 GitHub |
| 清华 TUNA 的 github-release | 没有 git-for-windows 目录（404） |
| **npmmirror 二进制镜像** | **可用**：`https://registry.npmmirror.com/-/binary/git-for-windows/` |

### 4. 当前用户是管理员，但进程是筛选令牌

`whoami /groups` 里 Administrators 显示 "Group used for deny only"——说明是 UAC 筛选令牌，
所以安装必须走一次提权；某些自动化环境里弹不出 UAC，就完全装不了。

## 二、认证（GCM / Token）

### 5. 最重要的一个：`credential.helper=manager` 但 GCM 找不到

**现象**：每次 `git push` 都退回老的用户名/密码提示，前面的授权全部白做。
**原因**：Git Credential Manager 装在 `C:\Program Files\Git\ucrt64\bin`，
而安装器往 PATH 里只加了 `C:\Program Files\Git\cmd`。`manager` 这个短名字解析不到，于是**静默失败**，退回提示。

**排查方法**：
```bash
git --exec-path                 # 看在哪儿找
git config --show-origin --get-all credential.helper   # 看 helper 来源和值
```
**解法**（不动 PATH，避免副作用）：
```bash
git config --global credential.helper "C:/PROGRA~1/Git/ucrt64/bin/GIT-CR~2.EXE"
```

### 6. 路径带空格，引号会丢

往配置里写 `!"C:/Program Files/Git/ucrt64/bin/git-credential-manager.exe"`，
经 PowerShell / Windows argv 传递后**引号被吃掉**，git 实际去执行 `C:/Program`：
```
C:/Program Files/Git/ucrt64/bin/git-credential-manager.exe store: line 1: C:/Program: No such file or directory
```
**解法**：用 **8.3 短路径**（`C:\PROGRA~1\...`），根本不含空格，不用引号。
查短路径：
```cmd
for %I in ("C:\Program Files\Git\ucrt64\bin\..\bin\git-credential-manager.exe") do @echo %~sI
```

### 7. 不要把 `ucrt64\bin` 加进 PATH

那个目录里不只有凭证管理器，还有 `find.exe`、`sort.exe`、`curl.exe`、`sh.exe` 一整套 Unix 工具，
加进 PATH 会**盖掉 Windows 自带的同名命令**，以后别的脚本会莫名其妙出错。
（安装器里那个第三选项 "Use Git and optional Unix tools from the Command Prompt" 就是干这个的，配了会警告。）

### 8. 浏览器授权回调落在 `127.0.0.1:57539`，被占用了

```
info: please complete authentication in your browser...
fatal: 响应状态代码不指示成功: 406 (Not Acceptable)
```
GCM 的浏览器授权需要本机回调端口，那个端口被宿主程序占着，回调打到了别人身上 → 406。
**解法**：改用设备码流程：
```bash
git config --global credential.gitHubAuthModes device
git push
# 弹窗给出 8 位码 → github.com/login/device → 输码 → Authorize
```

### 9. Token 当密码用（最稳的一条路）

```powershell
# 先把 token 复制到剪贴板
$t = Get-Clipboard
git push "https://<用户名>:$t@github.com/<用户名>/<仓库>.git" main:main
```
**注意顺序**：
- `$t = Get-Clipboard` 必须在截图之前执行——**截图会顶掉剪贴板**
- PowerShell 粘贴多行文本会**立即执行**，所以"先粘贴命令、再复制 token"这条路走不通
- token 生成后只显示一次，用复制图标，不要手抄（`l/I/1`、`0/O` 极易看错）

### 10. Token 泄露的处理

Token 等同于账号密码（`repo` 权限 = 所有仓库读写）。一旦出现在截图、聊天、日志里，
**立刻去 `github.com/settings/tokens` 删除重建**。删旧的不影响已推送的代码，只影响下次认证。

## 三、网络

### 11. `Recv failure: Connection was reset`

```
Writing objects: 100% (18/18), 760.74 KiB
error: RPC failed; curl 55 Send failure: Connection was reset
fatal: the remote end hung up unexpectedly
```
对象都打包上传完了，最后一步被重置。**解法**：
```bash
git config --global http.version HTTP/1.1
git config --global http.postBuffer 524288000
git config --global http.lowSpeedLimit 0
git config --global http.lowSpeedTime 999999
```
改完重推一次即成功。

### 12. `schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS`

出现在受限执行环境里（证书/凭据存储拿不到）。**解法**：临时换 OpenSSL 后端：
```bash
git -c http.sslBackend=openssl <命令>
```
普通桌面环境一般碰不到。

## 四、几条经验

1. **失败的每一步都要看退出码和完整报错**，不要只看最后一行。
2. **先分清是"认证失败"还是"网络失败"**：`401/403` 是认证，`Connection reset / 55` 是网络，两者解法完全不同。
3. **配置类问题优先查"值是否正确"，再查"程序能不能找到它"**——第 5 条就是典型的"配置写着对、但程序找不到"。
4. **不要为了省事去改 PATH**，副作用往往比问题本身大。
5. 装软件、跑安装包，**别放在受管理的目录里**。
